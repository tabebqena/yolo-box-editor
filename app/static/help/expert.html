Expert — extend the app

Add your own actions, filters and hooks, run your own scripts, and rebind every shortcut. Your files live in your user folder and are never touched by an update.

Where your files live

The app ships defaults in app/actions/, app/hooks/, app/filters/ and app/scripts/. Your copies live next to the installed app in your user folder (<home>/actions/, <home>/hooks/, <home>/filters/, <home>/scripts/, <home>/shortcuts.txt) and win on a name clash. Commands run with the working directory set to that folder.

Actions — a button that runs a command

An action is one YAML file in actions/. Build one in Settings → Actions → Create, or write it by hand:

# <home>/actions/Remove.yaml
steps:                  # one entry per line; stop on the first failure
  - rm -f {IMAGE_PATH}
  - rm -f {LABEL_PATH}
after_success:          # app actions to run afterwards
  - app_refresh_images_list

Each entry in steps / after_success is:

  • app_* — a built-in UI action (e.g. app_refresh_image);
  • backend_* — a built-in server action (currently backend_rescan_images);
  • action_<Name> — run another action inline;
  • anything else — a shell command.

Placeholders (leave them unquoted; the app quotes them for you): {IMAGE_PATH}, {LABEL_PATH}, {DATASET_PATH}, {DATA_YAML_PATH}, {IMAGE_INDEX}, {APP_DIR}, {HOME_DIR}, {APP_SCRIPT_DIR}, {USER_SCRIPT_DIR}, {PYTHON}, {PIPE_PATH}.

Always start a Python step with {PYTHON} rather than python, and name a helper explicitly: {PYTHON} {USER_SCRIPT_DIR}/helper.py …. Ship-style helpers live in app/scripts/ (class_filter.py, example.py, example_filter.py).

Filters — narrow the image list

A filter is one YAML file in filters/. It reads candidate image paths from {INPUT_PIPE} and writes the ones it keeps to {OUTPUT_PIPE}. Create one in Settings → Filters → Create, or by hand:

name: Sharp only
description: Keep sharp images
arguments:
  - name: threshold
    required: true
    default: "100"
steps:
  - {PYTHON} {USER_SCRIPT_DIR}/sharp.py {INPUT_PIPE} {OUTPUT_PIPE} --threshold {THRESHOLD}

Filter placeholders add {SPLIT}, {INPUT_PIPE} and {OUTPUT_PIPE} to the action list; each declared argument becomes an upper-cased token (threshold → {THRESHOLD}). An argument with options renders as a dropdown, and options: {DATASET_CLASS_NAMES} builds it from the loaded dataset. Chain up to 8 filters in Settings → Filters → Active chain. See app/filters/example.yaml and app/scripts/example_filter.py for a working starting point.

Hooks — run on an event

A hook is hooks/on_<event>.yaml; it runs automatically when the app fires that event (no button). It uses the same steps and placeholders as an action. Events include on_image_loaded, on_before_save, on_after_save, on_box_created and on_box_deleted.

# <home>/hooks/on_after_save.yaml
steps:
  - {PYTHON} {USER_SCRIPT_DIR}/helper.py {DATA_YAML_PATH} {IMAGE_PATH} {LABEL_PATH}

A steps failure in on_before_save aborts the save. Set active: false to switch a hook off everywhere, or untick Enabled for this dataset in Settings → Hooks.

Rebind shortcuts

Settings → Shortcuts → Edit: click a binding, then press the new combination. Modifier-only bindings (like Ctrl for force-draw) are captured by pressing and releasing the modifier; ↺ restores the shipped default. Or edit <home>/shortcuts.txt directly:

app_undo     <Ctrl+Z>     undo
MyAction     <Ctrl+Shift+R> run my action

A built-in app_* name or one of your action names may be bound; the label after > is free text shown in the UI. An unknown name is reported as a dismissible error.

Good to know

  • Every extension file carries api_version: 4. An older file is flagged outdated — open it with its YAML button and save to upgrade it (comments are kept); a newer file is blocked.
  • Actions and hooks can be disabled per dataset from their Existing list without deleting the file.
  • Read-only mode blocks extension writes as well as label edits.
